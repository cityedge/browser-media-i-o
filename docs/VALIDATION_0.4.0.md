2026-10-06、WindowsのChrome 154.0.8037.93 / Edge 154.0.4258.37で検証しました。
依存のMediabunny / AAC拡張は1.61.0を維持しています。

## APIと実出力

- Chrome: npm testのWeb 68件・Framecraft 6件が成功。
- Chrome / Edge: 追加したレート制御試験9件が各ブラウザーで成功。
- 従来入口と/publicの両方でVBR・CBR・CQPを実行。VideoEncoder.configureへ渡った方式・ビットレート・優先設定を観測。
- CQPでは各フレームのH.264 quantizer=23を確認。ビットレートを指定せずに符号化。
- 生成MP4はFFprobeで60映像パケット・H.264を確認。映像パケットの合計サイズとvideoBytesが一致。
- 未対応のCBRを能力応答で再現し、VBRへの自動変更・保存先のロックをせずUNSUPPORTEDを返すことを確認。
- 不正な方式・量子化値・エンコーダー優先、CQPとビットレートの併用をINVALID_ARGUMENTで拒否。

## 20 Mbps指定の比較

Chromeで、1280×720・30 fps・2秒の合成映像を比較しました。
「単純」は単色背景上で矩形が移動、「ノイズ」は各フレームで全画素を疑似乱数で更新する素材です。
数値は音声・MP4の管理情報を除いた平均映像Mbpsです。

| エンコーダー優先 | 方式 | 単純 | ノイズ |
|---|---|---:|---:|
| 自動 | VBR、20 Mbps要求 | 0.050 | 19.555 |
| 自動 | CBR、20 Mbps要求 | 0.045 | 20.239 |
| 自動 | CQP、QP 23 | 0.032 | 66.656 |
| ソフトウェア | VBR、20 Mbps要求 | 0.146 | 63.865 |
| ソフトウェア | CBR、20 Mbps要求 | 0.145 | 63.862 |

ハードウェア優先はこの環境では自動と同じ結果でした。
ソフトウェア優先のCQPは非対応で、UNSUPPORTEDを返しました。
優先指定はブラウザーへのヒントであり、実際のエンコーダーの識別・強制はできません。
合成映像の結果であり、利用アプリや特定の素材で同じ値になることを保証しません。
CBRでも短いクリップや単純な内容では大幅に低いレートになり、実装によっては目標を超える場合もあります。
APIに設定が届くことと、目標Mbpsに厳密に一致することを区別してください。
比較記録: [Chromeレート制御](reports/rate-control/windows-chrome-0.4.0.json)。

## 制約

既定のVBRと既存のAPIは維持しています。選択設定の能力検査と実出力には共通の構成処理を使います。
非対応時にライブラリが別方式へ自動変更することはありませんが、ブラウザー自身のレート制御挙動は変えません。
固定の最低Mbps、厳密な容量、2パスABR、FFmpegのCRF相当の制御は提供していません。
Safari / Firefox / モバイル端末と、報告された利用アプリのJIZURA合成素材そのものは未検証です。
設定の利用方法は[API](API.md#映像のレート制御040以降)を参照してください。
