# 0.5.0の検証範囲

2026-10-18、WindowsのChrome 155.0.8059.84で実施。

## 回帰試験

- `npm test`: 型検査、Web API 90件、Framecraft 6件が成功。
- MP3の39件は、WebAssemblyとブラウザのネイティブエンコーダーに依存せず実行。
- 従来のCBRは9種類のサンプルレート・モノラル／ステレオで旧エンコーダーとバイト単位で一致。
- VBR・ABRは9種類のサンプルレートでFFmpegによる独立デコード、再生時間、波形、フレーム構造を確認。
- file://・オフラインでVBR品質0／9とABR 96／192 kbpsを出力。フレームごとのビットレート変化、出力サイズの大小、Xingのフレーム数・バイト数・シーク索引を確認。
- 30秒のステレオVBRで左右の周波数・末尾の音声を確認。
- 不正な設定、短い無音、容量制限、キャンセルとWorker解放を確認。

## 配布と制約

通常版ZIPを日本語・空白を含むパスへ展開し、Chrome 155.0.8059.84／Edge 155.0.4283.45で
file://・オフラインのMP4／MP3保存、AACネイティブ／WASM経路、公開API単独バンドル、
キャンセル・再試行を確認しました。
さらに通常版・公開API版・MP3単体版の各配布JSでCBR／VBR／ABRを出力し、
両ブラウザ合計18ケースのコーデック・サンプルレート・チャンネル数・再生時間を確認しました。
EdgeではMP3の39件の回帰試験全体は完走していません。

各ZIPの全ファイルを同梱SHA256SUMSで照合し、対応ソースZIPの改修コード・ライセンス・
ビルド手順の収録を確認しました。対応ソースZIPを別フォルダーへ展開して依存を導入し、
再ビルドした3種類の配布JSが元のビルドとバイト単位で一致することも確認しています。
`npm run check:distribution` による文書リンク・npm収録範囲の検査も成功しています。

MP3用のWASM・外部ランタイムは追加していません。MP3専用JSは187,121バイトです。
VBRは旧LAME RH方式で、現行LAMEの既定VBR方式との品質一致は保証しません。
ABRは目標平均値で、素材・長さにより実測値は変わります。Xingは時間・シーク情報を含みますが、
ギャップレス再生用のエンコーダー遅延・末尾パディングのメタデータは付与しません。
音源全般の聴感評価や、長時間のVBR／ABR品質評価は未実施です。
Safari・Firefox・モバイル、長尺file://出力、直接ファイルストリーム保存は未検証です。

APIと設定例は[MP3ガイド](MP3.md)、以前のMP4試験は[0.4.0の検証](VALIDATION_0.4.0.md)を参照してください。
