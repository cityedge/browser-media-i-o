# 0.6.0の検証（2026-11-13）

Windows、Chrome 157.0.8103.50／Edge 157.0.4341.42。Mediabunny／AAC拡張は1.61.0を維持しています。
通常版ZIPを日本語・空白を含むパスへ展開し、両ブラウザでfile://（オフライン）とHTTPSの統合試験が成功しました。

## 映像コピー

- Closed GOPのBフレーム、VFR、90度回転、SAR 4:3、BT.709の素材を生成。
- 全区間コピーと複数区間の連結で、FFprobeの各圧縮パケットSHA-256と復号順序が元と一致。
- 元と出力をFFmpegで復号したフレームのハッシュが一致。表示時刻、寸法、SAR、回転、色を独立照合。
- コピー時にVideoEncoder／VideoDecoderをundefinedにして実行。公開API単独バンドルをDedicated Workerでも実行。
- Open GOP、誤った同期サンプル、sample description変更を理由付きで拒否。
- strict／inside、EOF、空区間、不正範囲、計画の複製・別入力への流用、変更不可性、中止・再試行を検査。
- 30000/1001 fpsの100保持区間、44.1 kHzで、累積サンプル数147147を確認。区間ごとの丸めの累積なし。

## 音声と保存

- 48 kHz stereo・80 kbpsの実出力は両ブラウザでWASM AAC。ネイティブ80 kbpsはこの環境では非対応。
- 192 kbpsでは実ネイティブAACも検査。事前確認と出力に同じ設定を使用。
- 先頭・接続点前後・末尾に置いた音声マーカーの測定値は期待位置と5 ms窓で一致。
- 元音声に250 msの開始オフセットを付け、アプリ側のPCM配置例と0.5倍のゲイン処理を通して出力。
  期待位置1.25／2.25／5.25秒に対し、検出位置1.245／2.245／5.245秒。
- 6秒の出力はMP4の表示時間6秒。生の復号PCMには768サンプルの末尾余剰があり、1 AACフレーム以内。
- PCMの不足／超過、レート不一致、NaN、初期化／供給／確定時の中止、書込失敗、Blob上限、再試行を検査。
- 成功時close、異常時abortの試行、ロック解放、PCM iteratorのfinallyを確認。
- file://・オフラインで実ファイルへの位置指定書き込みをNodeのディスクアダプターで検査。
- HTTPSでは実FileSystemWritableFileStream（OPFS）の保存・サイズ一致・ロック解放も検査。
  file://ではOPFSを使用できないため、ユーザーの保存先選択ダイアログ操作そのものは自動試験の対象外です。
- 日英のサンプルでファイル選択→区間計画→Blob保存→動画再生、390px幅の表示を確認。

## 2時間の逐次出力

160×96・25fps・7200秒、18万フレームの合成素材を使用しました。会議の実録画ではありません。
保持区間は0–1800、1810–3600、3610–7200秒。出力7180秒、48 kHz stereo AAC 80 kbpsです。
原音の全PCMなら約2.76 GB相当ですが、供給は4096サンプルのブロックです。

- 出力: 7,720,397バイト、位置指定write 10回、約79.4秒（このPCの1回の測定）。
- 先頭・接続後・中間・末尾の6地点で白い映像マーカーを確認。
- 対応する音声マーカーの最大誤差は0.125 ms。
- CDPによるメインページの使用JSヒープ最大約96.2 MB、backing storage最大約45.5 MB。
  1秒間隔の測定で、索引・muxerテーブルとGCの増減を含みます。ブラウザ全体・AAC Worker全体のメモリ上限を保証する値ではありません。
- 全映像データ・全PCM・全出力をまとめて保持せず完走。索引とMP4のサンプルテーブルはパケット数に応じて増えます。

検証コードは`scripts/test-video-copy.mjs`、`scripts/test-video-copy-long.mjs`。
生成素材・詳細JSON・スクリーンショットはtests/tmp/video-copy*へ出力し、Gitには含めません。
既存のWeb API 90件・アプリ6件と型検査は成功しています。
