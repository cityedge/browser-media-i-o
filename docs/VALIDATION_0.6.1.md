# 0.6.1開発版の検証（2026-11-13）

## 拒否原因と修正

提供されたZoom実録画は134,419,851バイト、映像4886秒（81分26秒）、1920×1080・25fps・H.264 High、音声48 kHz stereo AACでした。
映像は122,150パケット、同期位置169個、キーフレーム間隔最大30秒です。
v0.6.0では`GOP_STRUCTURE: Frame number gaps are not supported.`で停止しました。

SPSのgap許可フラグだけで拒否していた条件を変更し、許可フラグがある素材の各pictureについて、直前の参照pictureとのframe_numの関係を確認します。
IDR、番号の桁あふれ、複数sliceを考慮し、実際の不連続や追加のMMCO解釈が必要な場合は拒否します。
元素材のSPS/PPSは全期間同一で、全パケットが既存のIDR・時刻・表示情報の検査にも合格しました。

## 実録画の出力（Chrome）

Chrome 157.0.8103.50、file://、オフライン。映像のVideoEncoder／VideoDecoderをundefinedにして実行しています。
ストリーム保存は位置指定書込をNodeのディスクアダプターへ転送し、実ファイルのclose・ロック解放を確認しました。

| 試験 | 出力時間 | 映像パケット数 | 出力バイト数 |
|---|---:|---:|---:|
| 全映像コピー・音声なし | 4886秒 | 122150 | 86418616 |
| 3区間連結・加工済みPCMからAAC | 4764.68秒 | 119117 | 128235830 |

音声付きの実保持区間は1.32–1178.32、1238.32–3578.32、3638.32–4886秒。
既存の`inside`計画に従い、同じ区間から音声を読み、各PCMサンプルへ0.5倍のゲインを適用しています。
音声は48 kHz stereo・80 kbps、既存WASM AACを使用。入力サンプル数228704640は計画と一致しました。

- 両出力について、全映像パケットの圧縮ペイロードSHA-256と表示時刻を元の保持区間と照合し、一致。
- 元と出力の解像度・SAR・色範囲・primaries・transfer・matrixが一致。
- FFmpegの独立デコードで、全映像出力の先頭／中間／末尾、音声付き出力の各区間の先頭／中間／末尾（合計12窓）の画像ハッシュが一致。
- 音声付き出力の各接続後の3秒波形を独立デコードし、元音声との同時刻相関0.996以上、音量比0.496–0.502を確認。
- このPCの1回の測定で、全映像の出力約6.2秒、音声付きの出力約104.5秒。解析・独立照合時間は含まず、他環境の性能保証ではありません。

## 回帰試験と制約

Edge 157.0.4341.42でも同じ実録画を全期間解析し、先頭・中間・末尾から197.68秒を連結して音声付きストリーム保存を確認しました。
4942パケットの圧縮データと9窓の画像が一致し、音声サンプル数9488640は計画と一致。
確認した有音の2窓で波形相関0.996以上・音量比約0.5。末尾側の確認窓は元音声が無音のため、相関による時刻評価の対象外です。

SPSのgap許可フラグだけを立てた合成素材が通常モードで出力でき、復号画像が元と一致することを確認。
一方、実際のframe_numを不連続にした合成素材は`GOP_STRUCTURE`で拒否されることを確認しました。
既存の映像コピー統合試験（Bフレーム、VFR、回転、SAR、色、AAC、異常終了、Worker）も成功しています。
`npm test`全体も成功し、型検査・Web API 90件・アプリ6件・gap回帰試験・映像コピー統合試験を確認しました。

実録画・変換後のメディアと詳細JSONはローカルだけに保存し、Git／対応ソースZIPへ含めません。
試験コードは`scripts/test-video-copy-zoom.mjs`と`scripts/test-video-copy-gaps.mjs`です。
全フレームの独立デコード比較ではなく、全圧縮パケットの比較と指定地点の画像比較です。
今回の修正は通常検査でのZoom素材対応で、警告付き`validation:'container'`、`snap:'outside'`の追加要望はまだ含みません。
